# 图形渲染方向出题参考

子方向口径：光栅化/光线追踪管线、Shader、光照材质与后处理；三维网格/曲面建模、几何变换、过程式生成与纹理；骨骼/蒙皮动画、粒子、体素与实时场景组织。
要求基于真实项目提出真实工程需求，不要为了凑子方向硬造题。跨方向（例如渲染 + 引擎机制 + 图像算法）边界说不清时选「其他」。

## 先看容器能力再选题

容器里只有 node/npm/yarn、gcc/g++/make、python3（无 pip），没有 GPU、没有 cmake、不是 root。所以：

- **适合**：TypeScript/JavaScript 的 WebGL/WebGL2/WebGPU、three.js、Babylon.js、regl、PixiJS 项目（npm 装依赖，模型能 build、跑单测）；
  纯 C/C++ 的软件光栅化器/光线追踪器（make + g++，输出 PPM/PNG 文件，模型能自己跑出图）；
  shader 代码本身的修改（GLSL/WGSL），配合能在 node 里跑的单测或离线渲染。
- **慎选**：依赖 CMake、Vulkan SDK、GLFW/SDL 系统库的原生项目（模型在容器里编不过，会把时间花在环境上；
  如果就是想考环境/构建问题，题目里要说清楚，并在难度判断里算进去）。
- **录屏在 Mac 本机做**：Web 项目在 Chrome 里跑；离线渲染器在 Terminal 里跑出图，再用浏览器或预览打开结果。

## 方向示例（只作发散，不要照抄；同一 repo 不要出雷同题）

| 类别 | 可以考的真实需求形态 | 难点来源 |
|---|---|---|
| 阴影 | 给已有前向渲染器加级联阴影（CSM），处理级联切分、texel snapping 防抖、级联过渡 | 多 pass 数据流、精度与稳定性取舍 |
| 光照 | 在已有 PBR 管线里补 IBL（预滤波环境图 + BRDF LUT），保持与现有材质参数兼容 | 能量守恒、色彩空间、资源生命周期 |
| 后处理 | 在后处理链里加 TAA（运动向量、历史帧拒绝、jitter），不能破坏已有 bloom/tonemap 顺序 | 跨 pass 状态、鬼影与闪烁的取舍 |
| 管线迁移 | 把 WebGL1 渲染器的一部分迁到 WebGL2/WebGPU，保留旧路径做降级 | 兼容性、API 语义差异 |
| 光追 | 给 CPU 路径追踪器加 BVH + 多重重要性采样，结果需与原实现统计一致 | 正确性依赖大量边界、性能 |
| 几何 | 网格简化/LOD 生成并在运行时按屏幕误差切换，避免 popping | 拓扑约束、误差度量 |
| 动画 | glTF 查看器里把 CPU 蒙皮改成 GPU 蒙皮，支持多套骨骼与 morph target 叠加 | 数据布局、着色器与 CPU 同步 |
| 场景组织 | 给实例化渲染加视锥 + 遮挡剔除、按材质排序批处理，修正透明物体排序 | 正确性与性能相互牵制 |
| Bugfix | z-fighting/深度精度（reversed-Z）、sRGB 双重伽马、法线贴图切线空间错误、MSAA 下的 resolve 问题 | 需要定位根因而非改表象 |
| 体素/过程式 | 体素地形的 greedy meshing + 分块增量重建，编辑时不能整图重建 | 增量更新与一致性 |

## 题面写法提醒

- 像真实用户交代需求：说清目标、现有系统约束、不能破坏的东西、验收时会看什么画面或数据。
- 至少有两条互相牵制的约束（例如「画面稳定」和「不能增加超过一个 pass」），这样才是困难题。
- 不要把测试当主交付物（除非任务类型选「质量保障」）。

## 雷同题禁区（命中会被 `prompt` 阻断）

贪吃蛇、打砖块、俄罗斯方块、坦克大战及变种；粒子/物理模拟演示（星系、烟花、落沙、布料）；塔防、2D 解谜、潜行、平台跳跃；
喂食小动物；记忆翻牌、连连看；五子棋等棋类、2048、扫雷、打地鼠。
注意：真实渲染引擎里的粒子系统、GPU 粒子排序这类工程需求是允许的，独立的「做一个烟花/星系效果」不允许。
