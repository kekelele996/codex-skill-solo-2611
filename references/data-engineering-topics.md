# 数据工程分类出题参考

最新分类把数据工程细分为「数据采集、爬虫与 RPA」「数仓与数据湖」「数据分析与数据应用」。默认子方向为「数仓与数据湖」，但应从真实工程的标签继承实际分类。

## 选题原则

- 从仓库里已经存在的真实流程出发，从源码、数据结构、接口、脚本或测试中找冲突，不先写一个听起来宏大的 ETL 需求再硬套项目。
- 「其他」不是泛后台代称。可以包含采集后的清洗入库、异构数据集成、批处理调度、增量同步、回填、质量隔离、血缘、跨系统对账、CDC 或数据迁移，但核心必须围绕数据从哪来、怎样变换、写到哪、失真或失败时怎样恢复。
- 至少有一个跨对象不变量，例如源记录数与入库数、批次状态与分区可见性、口径版本与重算结果、异常隔离数与总输入数、源库与数仓对账结果。
- 困难题必须有人类工程师需要权衡的取舍。只加字段、加筛选、加导出按钮、加一张结果表，一律按中等处理。

## 可用的真实工程形态

| 形态 | 可以考的业务冲突 | 常见复杂点 |
|---|---|---|
| 增量采集与入库 | 上游分页/游标与本地水位不一致，迟到记录会落进旧窗口 | 增量/全量切换、游标推进、重复消费、断点续跑 |
| 多源合并 | 客户主数据和订单明细来自不同系统，字段缺失时业务归属冲突 | 事实来源、优先级、字段级合并、冲突留痕 |
| 批次回填与重算 | 规则升级后历史批次需要重跑，但不能覆盖正在发布的数据 | 批次隔离、版本兼容、原子切换、失败恢复 |
| 数据质量隔离 | 一条坏记录不能拖垮整批，但也不能静默丢弃 | 分区提交、隔离原因、重放、审计计数 |
| 跨系统对账 | 源库、数仓和报表侧计数或金额对不上，需要定位并修复 | 口径统一、差异分类、修复幂等、复核对账 |
| CDC/事件同步 | 同一业务变更被重复投递，或旧事件晚到覆盖新值 | 顺序、幂等、版本比较、死信与重放 |
| Schema 演进 | 上游新增/删除字段后旧任务仍要能跑，新分区不能混入坏行 | 兼容策略、迁移、默认值、数据质量边界 |
| 采集/RPA 编排 | 页面或接口不稳定，重试可能重复提交，失败后无法知道做到哪一步 | 状态机、幂等键、失败恢复、人工接管点 |

## 项目形态与容器约束

- 容器内有 Node 22、npm/yarn、Python 3.11 标准库、gcc/g++/make、git、curl；没有 pip、Go、Java、Rust、GPU，也不是 root。
- 优先选择仓库里已有依赖能构建运行的 Node/TypeScript 服务、Python 标准库任务、C/C++ CLI/批处理，或自带依赖锁的纯后端项目。
- 不要求模型完成需要外部云账号、生产数据库、Kafka 集群、Airflow 服务或真实第三方网站的验收。
- 外部系统用仓库已有的本地 fixture、SQLite、文件、HTTP mock 或内存实现承载；题面只写业务结果，不指定技术栈。
- 录屏可以在 Terminal 中展示导入、处理、回读和对账结果。若本轮新增或修改了用户可见页面、页面交互
  或页面结果展示，且应用能够真实启动并到达页面，就必须在 Terminal 中录制启动过程，再用本次新开的独立
  Chrome 录制对应页面的登录/入口、真实操作链路和最终结果，不能只录测试命令或只展示结果页。若真实启动
  错误发生在页面可达之前，改用 Terminal 完整录制失败过程，不要另起一套成功环境补页面。

## 雷同与过简禁区

- `CSV 看板`、`Streamlit`、`数据大屏`、`Excel 导入工具`、`爬虫入门`、静态页面抓取演示等成品形态直接拒绝。
- 单纯的「换一个字段名」「补一个筛选」「把脚本改成定时执行」「加一个结果列表」不能标困难。
- 只靠堆很多来源、很多表、很多步骤，也要判中等；必须有互相牵制的约束或失败后的恢复风险。
- 真实数据工程任务可以输出报表或对账结果，但不能把交付物矮化成一张展示型看板。

## 题面示例方向（只作发散，不照抄）

- 现有日批任务按文件到达顺序追加数据，迟到记录会被下一批的同一主键覆盖。要求在批次可见前完成去重和版本裁决，重跑同一批不能新增行，失败后续跑仍能恢复到未处理位置。
- 客户主数据来自两个系统，当前合并逻辑总是后写覆盖。要求保留来源和时间依据，冲突字段可追溯到具体来源，重放一批历史事件不会把已撤回的数据恢复出来。
- 报表侧与源库总记录数对不上。要求把缺失、重复、状态差异分开统计，并能只修复异常分区，不动已通过核对的数据。

## 题面写法

像业务方交代当前问题和期望结果。给出使用者能观察到的失败后果，例如「重复跑同一批后订单数翻倍」「上游补发一条旧事件，地址被改回旧值」「回填失败后新分区对线上不可见」。不要把文件路径、函数名、修法、端口或技术栈写进题面；这些放到难度论证和轨迹证据里。
